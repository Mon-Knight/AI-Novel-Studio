# AI Novel Studio 版本路线图（version-roadmap.md）

> 项目名称：AI Novel Studio  
> 项目路径：`F:\ai-novel-studio`  
> 技术路线：Tauri + React + TypeScript + SQLite  
> 目标平台：Windows 桌面端  
> 开发方式：VS Code + Copilot / Agent 辅助开发  
> 项目定位：通过不同提示词调度 AI API，让 AI 在小说创作流程中承担不同分工，辅助用户逐章完成一本长篇小说。

---

## 1. 项目总体目标

AI Novel Studio 的目标不是普通码字软件，也不是一次性生成整本小说的网站，而是一个面向长篇小说创作的 Windows 桌面软件。

核心目标：

1. 用户创建小说作品。
2. 用户提供大致世界背景、主角信息、主角特殊能力、规则体系、分卷大纲、章节大纲。
3. 系统通过不同提示词调用 AI API，让 AI 分别承担设定整理、角色生成、剧情事件推理、正文生成、润色、质量检查、章节总结等任务。
4. 用户在写作工作台中选择本章要调用的设定、角色、事件、风格方案和输出控制方案。
5. AI 生成一章正文到中间正文编辑区。
6. 用户可以修改、重生成、润色、确认采用。
7. 用户确认采用后，系统自动总结本章内容，更新上下文、角色状态、剧情进度，为下一章生成提供连续性支持。

最终形态：

```text
作品管理首页
↓
作品详情 / 创作资产管理
↓
章节写作工作台
↓
AI 生成正文
↓
用户修改 / 重生成 / 润色
↓
确认采用
↓
自动总结上下文
↓
继续下一章
```

## 2. 版本规划原则

### 2.1 先 UI 框架，后 AI 能力

前期优先完成桌面软件结构和写作工作台布局，不要一开始就接入复杂 AI 逻辑。

推荐顺序：

```text
项目壳 → 首页 UI → 工作台 UI → 本地数据 → AI 设置 → AI 生成闭环 → 风格/角色/事件 → 上下文总结 → 质量检查
```

### 2.2 主界面负责资产准备，工作台负责调用资产

主界面 / 作品详情页负责：

- 世界背景
- 规则体系
- 主角设定
- 分卷大纲
- 章节大纲
- 角色库
- 风格方案
- 输出控制方案
- TXT / JSON 导入

写作工作台负责：

- 选择当前章节
- 调用已有设定
- 选择出场角色
- 选择剧情事件
- 选择风格方案
- 选择输出控制方案
- 生成正文
- 修改 / 重生成 / 润色 / 检查 / 确认采用

### 2.3 AI 功能必须围绕“逐章完成小说”

所有 AI 功能都应服务于正文生成，不做与小说正文创作无关的复杂功能。

优先级最高的是：

```text
章节正文生成
章节重生成
章节润色
章节质量检查
章节总结
上下文延续
```

### 2.4 每个版本必须可运行、可回退、可备份

每个版本完成后必须：

1. 能正常启动桌面开发环境。
2. 不能破坏已有页面。
3. 不能提交 `node_modules`、API Key、`.env.local`。
4. 必须提交 Git。
5. 必须推送 GitHub。
6. 稳定版本必须打 tag。

推荐命令：

```powershell
git status
git add .
git commit -m "feat: complete vX.X.X ..."
git tag vX.X.X
git push origin main
git push origin vX.X.X
```

  └─ Verification Engine（自我验证）

Phase 3: Autonomous（v3.x 系列）
  ├─ Multi-Agent Workflow（多 Agent 协作）
  ├─ Autonomous Creation（自主创作流程）
  └─ Creative Collaboration（人机协作模式）

### Agent 化关键能力演进

| 能力 | v1.x（当前） | v2.x（Agent 化） | v3.x（Autonomous） |
|------|------------|-----------------|-------------------|
| Rules | 静态文档 | 动态检查 | 自动执行 |
| Planning | 人工拆解 | Agent 辅助 | Agent 自主 |
| Memory | 章节上下文 | 长期记忆 | 语义记忆 |
| Tool Calling | 无 | 工具注册 | 自主选择 |
| Multi-Agent | 无 | 无 | 协作网络 |

## 12. v0.9.0：角色候选与剧情事件推荐

### 目标

让 AI 辅助生成本章可用角色和可选剧情事件，用户选择后再进入正文生成。

### 核心任务

1. 创建角色库。
2. 支持 AI 根据世界背景、规则体系和章节大纲生成候选角色。
3. 用户选择候选角色后，角色进入已生成角色库。
4. 已生成角色保存关系、目标、性格限制、行为边界、不能做出的行为。
5. 工作台可选择本章出场角色。
6. 支持 AI 根据分卷大纲、章节大纲、前文总结、角色状态推荐剧情事件。
7. 用户选择本章必须发生的事件。
8. 生成正文时自动加载所选角色和事件。

### 角色连续性要求

第二次调用已生成角色时，不允许重新随机生成该角色。必须读取已有角色资料：

```text
角色关系
当前目标
性格限制
行为边界
不能做出的行为
已出场章节
上一章状态
```

### 事件推荐原则

AI 可以提供多个事件选项，但最终发生什么必须由用户选择。

### 验收标准

## 18. 开发执行规则

### 18.1 每个版本开始前

Agent 必须先检查：

```powershell
git status
npm install
npm run dev
```

确认当前项目可以运行后再修改。

### 18.2 每个版本开发中

必须遵守：

1. 不要一次性修改过多无关模块。
2. 不要破坏已有页面。
3. 不要删除已有数据结构，除非任务明确要求。
4. 不要把所有代码写进一个文件。
5. 不要写死 API Key。
6. 不要提交 `node_modules`。
7. 不要把 UI 做成普通后台管理系统。
8. 不要让工作台变成复杂设置页。

### 18.3 每个版本完成后

必须输出完成汇报：

```text
一、版本号
二、核心目标
三、完成内容
四、修改文件
五、运行结果
六、Git 提交与 tag
七、遗留问题
```

### 18.4 Git 提交规则

提交信息建议格式：

```text
feat: add writing workspace layout
fix: repair right dock collapse behavior
docs: update product design
refactor: split novel components
style: polish home page layout
test: add basic route tests
chore: update project config
```

## 19. 优先级判断规则

当功能冲突时，按以下优先级判断：

```text
第一优先级：能否帮助用户生成下一章正文
第二优先级：能否提高长篇连续性
第三优先级：能否减少用户重复填写
第四优先级：能否改善写作工作台体验
第五优先级：能否提升导入导出和备份安全
第六优先级：界面装饰和非核心功能
```

不符合上述优先级的功能，不应在 v1.0.0 之前优先开发。
