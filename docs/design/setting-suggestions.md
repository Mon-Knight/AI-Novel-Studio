# 设定库 AI 推演设计

> 当前状态：✅ v1.7.9～v1.7.10 基础版已实现  
> 入口：`/#/novels/:id/setting-suggestions`、`/#/worlds/:worldId/lore/suggestions`

---

## 1. 功能定位

设定库 AI 推演用于在正式创作资产之外生成“可选设定候选”。它服务于长篇小说前期和中期扩展，帮助用户补充角色、势力、地点、规则，但不替用户自动决定世界观。

核心原则：

```text
AI 生成候选
→ 用户查看
→ 用户采纳 / 编辑后采纳 / 废弃
→ 采纳后才写入正式资产
```

---

## 2. 支持的候选类型

| 类型 | 用途 | 当前采纳目标 |
|------|------|--------------|
| 角色 | 生成可加入角色库的人物候选 | 角色库 |
| 势力 | 生成组织、阵营、门派、公司等候选 | 世界设定条目 |
| 地点 | 生成城市、区域、据点、遗迹等候选 | 世界设定条目 |
| 规则 | 生成世界规则、能力规则、禁忌、代价等候选 | 规则体系 |

> 势力库和地点库目前尚未拆分成独立正式资产模块，所以 v1.7.10 采用“写入世界设定条目”的保守策略。后续版本可以在新增正式模块后迁移采纳目标。

---

## 3. 状态流转

| 状态 | 含义 |
|------|------|
| `pending` | 待处理，用户尚未决定 |
| `adopted` | 原样采纳 |
| `edited_adopted` | 用户编辑 JSON 后采纳 |
| `discarded` | 废弃，不写入正式资产 |

安全约束：

- 只有 `pending` 候选可以执行采纳或废弃。
- 已采纳、编辑后采纳、已废弃候选不能重复采纳。
- 采纳动作由用户点击触发，服务层不自动采纳 AI 输出。

---

## 4. 页面结构

设定推演页面采用桌面工作台式布局：

- 左侧：生成参数面板。
- 右侧：候选列表、状态筛选、Prompt / 原始输出查看。
- 弹窗：编辑后采纳 JSON。

生成参数包括：

- 作品选择
- 生成类型
- 世界类型
- 参考风格
- 候选数量
- 用户补充要求
- 是否引用已有世界设定
- 是否引用已有角色等资产

---

## 5. 服务层设计

核心服务：`src/services/settingSuggestions/settingSuggestionService.ts`

职责：

- 构建设定推演 Prompt。
- 调用统一 AI 客户端。
- 创建 AI 任务记录。
- 解析 AI 返回的 JSON。
- 保存候选池。
- 执行采纳、编辑后采纳、废弃。

候选池当前保存在 LocalStorage，键名为 `ai_novel_studio_setting_suggestions`。这样可以避免在 v1.7.x 末尾新增数据库 schema，同时满足“候选不等于正式资产”的边界。

---

## 6. Prompt 安全规则

设定推演 Prompt 必须明确：

- 输出为原创设定候选。
- 不得照搬受版权保护作品的人名、地名、组织名、专有规则或标志性桥段。
- 只能使用参考风格的抽象特征，例如节奏、复杂度、氛围。
- 输出必须是 JSON，便于解析和用户确认。
- AI 只提供候选，不代表正式写入。

---

## 7. Mock 模式

Mock AI 客户端已支持 `setting_suggestion_generate`，可在无 API Key 的情况下生成结构化候选：

- 角色候选
- 势力候选
- 地点候选
- 规则候选

这让 v1.7.9～v1.7.10 的完整流程可以在本地离线验证。

---

## 8. 当前限制

- 候选池尚未进入 SQLite，卸载应用或清理浏览器数据可能丢失候选记录。
- 势力、地点尚未拥有独立正式 CRUD 模块。
- 编辑后采纳以 JSON 文本方式修改，后续可升级为字段化表单。
- 当前测试以静态回归检查为主，尚未引入端到端自动化。
