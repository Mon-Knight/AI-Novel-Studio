# 创作工作流指南

> 基线：v3.7.0。本文描述当前默认主路径，不表示未列出的页面已删除。
> 本次交互、候选与世界规则修复仍在集成验证中；以下说明是操作口径同步，不代表统一验收通过。先前实测见 [三万字桌面记录](../../reports/desktop-real-novel-30000-2026-10-15.md)，本批定向检查、构建及桌面复验进度见 [流程修复记录](../../reports/real-use-flow-repairs-2026-10-16.md)。R4 live 云端仍 NOT VERIFIED。

推荐顺序：

```text
创建作品，进入会话讨论构思
→ 确认准备模板、背景规则与人物
→ 生成大纲，再逐章生成候选
→ 写作工作台审阅、编辑、保存、采用
→ 章节总结沉淀上下文
→ 继续下一章
```

## 1. 准备作品

1. 从侧栏「项目库」或作品概览新建小说。
   从作品页面点击「新建会话」或按 `Ctrl+N`，工作台会先选择该作品、等待章节加载，再打开新会话；作品缺失时返回该作品详情，不会沿用上一次作品。
2. 在作品详情填写世界背景、规则体系和主角设定。世界与规则可先写正文，再按需补充性质、条件、范围、故事时间与揭示、认知、代价上限、例外和来源依赖；八类世界参数可留未知或不适用，不必先写完整百科。世界背景卡与规则条目首屏显示标题、正文摘要和分组事实：性质、范围、限制/代价、角色知道（认知状态与知情者）以及八类参数进度；来源与依赖、参数示例在对应分组按需展开，未填项是待补缺口而不是错误。修改或停用前先「预览变更影响」，看清拟改全文、来源与可能受影响的采用章，再确认保存；规则永久删除仍可用，建议优先停用，有明确依赖时会阻断。详见 [世界规则契约](../design/world-rule-contract.md)。
   主角设定会显示人物备注；发现能力、限制或备注与正式世界规则冲突时，打开主角“编辑”，在相应字段中修正并保存。人物档案中另有行为边界时也要核对。此操作修改人物资料，不直接改写已采用正文。
   在角色库点击“编辑角色”，可修改名称、角色类型、身份、阵营、与主角关系、性格、目标、行为限制和禁止行为。已绑定主角设定的角色保持主角类型；普通角色改为主角或配角时，角色身份标记同步更新，不自动建立主角设定绑定。若保存时档案已变化，输入会保留；刷新查看最新正式档案，明确核对后再保存，未改字段沿用最新版本。
3. 建立分卷与章节，至少写好本章大纲和目标字数。
4. 需要时在角色库、风格方案、参考资料中补资产。空白项目也可以先在工作台发送创作目标，按提示生成待确认的设定与规划候选。

## 2. 在创作工作台生成候选

AI 根据对话整理作品定位、叙事约定、时空社会背景、世界规则与代价、人物、主要冲突及后续规划依据。关键缺项先询问；可回答“其余按已确定的信息推演”，AI 会区分已确认信息、推演与待决定问题，再请求确认。生成的“创作准备模板”仍是候选，显式应用后才作为背景条目显示在作品概览；人物随后用独立人物候选确认。模块外框高度固定，长内容在模块内滚动，背景和规则可展开完整正文。

模板依据[番茄官方作家课堂](https://fanqienovel.com/writer/zone/tutorial?tab=1)及[官方开书准备课程](https://fanqienovel.com/writer/zone/article/7410314379003969598)的常见准备方向归纳，是本软件的通用工作模板，可按题材调整。

1. 打开应用后默认进入「创作工作台」（`/`）。
2. 选择小说项目，用「新建会话」开始对话，直接交流构思，例如「我想写现实悬疑，先聊聊人物和背景」。桌面真实 API 由实际模型回应与追问，确定意图后通过工具执行；纯讨论不强行生成产物。背景和规则、人物确认采用后，才推进大纲与正文。
3. 新建会话时选择目标章节与模型；同一会话可在输入区模型下拉切换已加载模型或设置中心保存的 API 模型，保存成功后下一回合生效，重启后保留选择。选模型和发送不进行额外能力探测，实际调用失败在对话里显示。准备发送、运行中、模型保存中和归档时不可切换；已有回合及候选保留原模型，旧回合重试仍用原模型。想用新模型处理旧要求时，请发送新回合。需要调整字数时，可在本会话先发送「本任务目标字数设为 3200 字」，确认本地回执后再写章；也可发送「生成下一章，目标 3200 字」。这只调整会话的生成目标，不改章节大纲或正式正文；设置页的字数预览不是任务设置。
4. 对话里查看工具调用、错误和产物卡片。连续成功且无警告的只读读取会合并成「已读取创作材料 · N 项」，展开可见具体工具；运行中、失败、含警告或证据不完整的读取仍逐条显示，不会被折叠。候选卡首屏显示可识别的作品/章节名称、候选序号、来源模型、基线与下一步，校验错误、读取失败和冲突状态直接可见。候选不会自动写成正式正文。
   目标确认接收后，输入框立即清空；你可以继续写下一条草稿，当前运行结束或失败不会覆盖它。发送前校验失败仍保留原草稿。已发送回合失败时，可从对话里的失败记录显式重试。
5. 桌面端使用真实 API 模型时，写章默认由 Writing SubAgent 读取上下文并提交候选；Mock 与本地模型走确定性写章管线。非首章须先有可读取的前章采用稿。SubAgent 的待复核草稿不是已发布候选，完整性硬错误会在预算内修复，预算耗尽则保留失败证据并等待你显式重试；不会先产生可采用卡片再悄悄删除。需要关闭 SubAgent 时，见 [用户指南第 8 节](../user-guide.md)。
6. 结构化产物（大纲、角色、事件、设定、章节总结）须在卡片上显式「应用到作品」；章节正文须确认进入审阅。质量/风格报告只有「标记已阅」，不代表写入作品。
7. 对候选点「要求修改」或「带出全部意见」时，输入区会出现该候选的修订来源标签。意见和来源分开保存：可继续输入自己的话，来源会随发送与失败重试一起复验；来源失效或已绑定另一候选时需要重新选择，不会自动改用最新候选。全书规划属于作品候选，修订无需绑定章节。重启后，可点原卡片的「继续填写修订意见」恢复这份候选的来源；未发送草稿只保留当前应用会话，需要重新填写意见。可明确发送「生成全书规划候选，不生成正文」；规划与正文分开识别，同一动作的相互矛盾要求仍会提示澄清。
8. 生成设定时可明确发送「生成世界观和规则系统候选」或「生成世界与规则设定候选」。补充要求可以提及主角和人物行为，仍按设定生成处理；候选须审阅并确认应用后才成为正式上下文。
9. 需要更大正文空间时，点击任务头的「专注写作」。它只在当前会话临时隐藏项目树和未固定的辅助面板；不改变侧栏偏好、不停止后台任务、不清除草稿。再次点击「退出专注」或按 Ctrl+K 可恢复。上下文、产物和插件默认是临时参考面板，确实需要并排查看时再点击「固定参考面板」。
10. 长对话初始只读取最近 8 个完整用户轮次，可加载更早记录或定位候选；候选正文按需读取。同一任务临时刷新失败会保留上次画面并显示未更新提示，明确已删除的任务不会继续可操作。不同任务的候选决定互不占用同一把忙碌锁；同任务的重复点击仍被保护。

如果出现 `DSH_CONTEXT_INCOMPLETE`，表示本回合的必需材料缺少完整读取回执或超出读取预算，不是 API Key 失效。更新软件后重新打开并显式重试，让当前 Gateway 重新读取材料；仍有材料预算提示时，先补全或缩小对应世界、规则或章节工程材料。已有失败记录和待处理候选保留，重试不会自动采用正文。

Memory 无命中、片段截断或检索预算不完整会单独提示，不会仅因工具成功就折叠成「已读取创作材料」。这些提示不是语义质量通过。

新会话优先继承本作品最近一次模型选择，按选择的保存时间判断；后台任务进度更新不会抢占默认，继承已有选择也不会把它变成一次新的选择。旧记录缺少选择时间时，按原会话创建时间作保守回退。发送前仍可核对或更换输入区的模型，重试继续使用失败回合的冻结模型。

## 3. 在写作工作台审阅与采用

采用后，编辑器会提示核对正文事实与源材料。点「核对源设定」可并排查看原候选与采用稿的改写片段，并展开全部启用背景和规则；文字匹配只帮助定位，不代表已证明矛盾。修改设定仍须预览影响、明确确认后保存。设定版本冲突时，可点「刷新正式版本（保留输入）」查看最新材料，显式更新编辑基线后重新预览并确认；刷新会撤销旧预览确认。若采用正文已变化，需重新打开核对，不能继续沿用旧正文依据。人物档案、主角资料及本章/后章大纲有各自的定位入口；关闭或离开核对窗口前会提示处理尚未保存的输入。

「核对本章与后章大纲」直接进入本章的大纲编辑器，可切换其他章节核对。已有章节的“编辑章节”显示采用章纲并提供同一编辑入口；章纲修改应保存为版本并明确采用。本章目标、标题、所属分卷、目标字数和状态在章节资料中独立保存，只提交实际修改的字段。若章节或采用章纲已被其他入口更新，保存会停止并保留输入；刷新查看完整最新资料，确认新基线后，原先未改的字段会沿用最新值。

1. 从产物卡片或项目页进入「章节审阅」。
2. 阅读候选，可显式进入编辑、保存草稿。
3. 确认无误后点击「采用」。桌面端在同一 SQLite 事务中切换正式正文并失效过期的旧章节上下文；浏览器开发回退同步章节指针、状态和字数，并在上下文或授权消费失败时恢复本地快照。低置信度 `warning` 只是作者审阅提醒，不单独阻止采用；`error`、版本/哈希冲突、失效授权和不可验证的前章仍须先处理。
4. 授权状态分开显示：可继续审阅、已采用（查看正式正文）、已失效。若世界或规则在授权后发生变化，旧授权会失效并提示你要求修改、重新生成候选，不会自动重签。
5. 未修改候选可由你在任务对话中显式采用；这仍走权威候选校验、审阅授权、草稿保存与原子采用的同一条安全链，不是让模型直接写正文。
6. 右侧工具轨提供保存、草稿历史、章节准备、总结、排版和采用。这里没有独立的 AI 生成面板；生成入口在创作工作台。

## 4. 沉淀后再写下一章

章节总结状态会显示在编辑器中，可定位来源任务和待审阅候选；右侧总结入口也进入受治理的任务对话。拒绝后的重做携带当前采用稿与修改意见，仍需你确认发送。其他章节可以独立补总结，未应用的章节会继续显示上下文缺口。

新总结按已确认、推测、待查、计划标注断言并展示原文摘录。请检查摘录的完整语境，尤其是“尚未”“准备”“愿意”等限定；原文确有这句话不等于总结的推断必然成立。可针对单条断言将核对意见带入输入框，确认后再发送重做；旧总结缺少依据时会明确提示。若生成后采用正文又改变，应基于当前采用稿重新总结。

手动总结即使在读取材料或网络阶段失败，也会按保存的阶段与采用稿来源定位失败任务和原模型。点击某份总结的单条重做意见时，仍定位这份总结所属任务；同章其他会话较新的总结不会接管该入口。输入区已有未发送文字或修订来源时会保留并提示处理，不会替你清除来源或自动发送。

1. 在任务对话中采用正文后，回到该会话审阅自动总结，确认后「应用到作品」。也可选择已采用章节，明确发送「总结本章」及补充要求，审阅新的总结候选后再应用。手动总结须绑定当前采用稿；未采用正文、作品/会话不符或正文哈希异常时拒绝。
2. 回到创作工作台继续下一章，或发送「继续写」。
3. 已采用正文会进入长期 Memory，供后续检索；未采用候选不会污染正式事实。
4. 正文回合因网络等原因失败后，从失败记录点击「重试此回合」。重试中完成的规划步骤不会代替正文结果，原失败记录及冻结模型保留；有活动运行或已完成正文时仍不可重试。

## 5. 并行入口（不是默认主路径）

下列页面仍然可用，用于全书规划或资产推演，**不替代**工作台任务对话：

- **自主创作**：全书计划与候选队列，正式采用仍要回到章节审阅。
- **设定推演**：角色 / 势力 / 地点 / 规则候选，须用户采纳后才写入正式资产。
- **大纲页**：人工维护全书 / 分卷 / 章节大纲。保存为新版本后继续展示新版本；点击历史版本可查看对应内容，确认后另点“设为采用版本”。有未保存修改时先保存或恢复，再切换版本。编辑未采用版本会另存新版本，保持当前采用内容不被改写。
  桌面端保存当前采用的章纲，或把另一章纲版本设为采用时，会同时更新关联章节的章纲材料；任一写入失败则整体撤销。仅保存未采用的新版本不改变正式章节材料，章节目标仍需独立编辑。浏览器预览暂不支持保存或采用章纲，会明确提示使用桌面端。
- **AI 任务记录**：只读历史，不是新的生成入口。

## 当前限制

- 本批修复仍在集成，交互、候选来源与世界规则的最终结论以全部修复完成后的统一验收为准；本文不提供通过结论。
- 会话内的阅读位置、展开状态与跟随开关只在本机当前应用会话内恢复，不跨应用重启。
- 浏览器开发预览只提供本机规则/候选恢复与校验，不组成 SQLite 事务，也不替代桌面或云端证据。
- R4 live 云端只读验收尚未完成，不能把 Mock 或仓内 loopback 当成完整自主 Agent。
- 参考资料目前以 TXT 为主；EPUB / PDF 未开放。
- 质量检查与润色仍按既有章节工具进行，结果保存为新草稿或报告，不自动覆盖采用稿。
