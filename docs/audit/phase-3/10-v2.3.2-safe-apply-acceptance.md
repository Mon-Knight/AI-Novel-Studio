# v2.3.2 Safe Apply 验收报告

验收日期：2026-07-26
分支：`codex/v2.3.2-safe-apply`
基线：`v2.3.1`（`208e23c`）
目标：把有效设定候选通过用户确认、目标前置条件、单事务副作用和幂等重放安全创建为正式世界设定。

## 1. 范围结论

本版本新增 PlacementProposal、ApplyPlan 和 ArtifactTargetLink，只开放 `setting_candidates@1` 的单个候选创建一条 `world_setting`。生成候选后 Task 保持 completed；业务应用状态由 Plan/Link 表达，不改写 Artifact 或 Task 历史。

其他 Artifact 类型、批量/多目标 Apply、Provider 迁移、Tool Registry、Planner、Memory、自动续跑、Multi-Agent 和 Agent 自主写入均不在本版本实现。

## 2. 执行与安全不变量

- Proposal 与 Plan hash 从持久 Artifact 候选和目标前置条件重新计算，不接受 UI 自报内容。
- Proposal 整行不可更新/删除；Plan 身份和 effect 不可变，只允许合法状态边；Link 整行不可更新/删除。
- 每个 Plan 只包含一个 `create world_setting` effect，目标预分配且要求 version 0/不存在 hash。
- 用户确认时持久保存 `confirmedBy=user` 和时间，且只能确认一次。
- world_setting、ArtifactTargetLink、result JSON 和 Plan applied 在同一 SQLite `IMMEDIATE` 事务提交。
- 相同 operationId/planHash 重放返回首次目标和 Link，不重复写入；普通冲突不自动重放。
- targetId 碰撞记录 conflict，不覆盖既有世界设定。
- applied 重放重新读取并校验目标完整 hash；删除、修改或链接异常返回 `PLACEMENT_TARGET_CHANGED`。
- 浏览器 ephemeral 候选不创建 Placement 事实，也不能进入正式采用路径。

## 5. 真实 API 边界

v2.3.2 没有修改 Provider Adapter、HTTP 协议、Prompt、模型参数或网络入口，因此按用户“不要使用太多 API”和风险匹配测试要求，不重复真实 API 调用。v2.3.1 已如实记录的一次 8-token 真实连接尝试失败；本版本不使用 Mock 结果改写该结论。
