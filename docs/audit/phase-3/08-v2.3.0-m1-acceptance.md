# v2.3.0 M1 验收报告

验收日期：2026-07-26
分支：`codex/v2.3.0-m1`
基线：`v2.2.1`（`9125093`）
目标：建立后续 Provider、Planner、Memory 与 Multi-Agent 共用的持久执行事实层。

## 1. 范围结论

本版本完成 `AiTask`、`AiTaskAttempt`、三类 Snapshot、`ResultArtifact` 与 `ArtifactValidationIssue` 七类模型，以及 migration 005～011、受控 Tauri IPC、TypeScript 类型和薄服务 facade。

数据库升级只新增表、索引与触发器；未修改 `chapter_drafts`、`quality_check_reports` 或其他既有业务表形状，未迁移、删除或伪造 Legacy `ai_task_records` / `generation_jobs`。生产 Provider 与现有 AI 页面未迁移，因此本版本没有真实 API 调用。

## 2. 数据与执行不变量

- Task 与 Input / Context / Constraint Snapshot 在一个 `IMMEDIATE` 事务中创建。
- canonical requestHash 覆盖目标、预期 Artifact 契约、三类 Snapshot、正文/上下文/Prompt hash、预算、compiler 和白名单 Provider options。
- Attempt 使用 state revision CAS，同一 Task 最多一个 live Attempt；重试、取消、迟到响应与提交未知重放均有动态测试。
- Artifact 与 Task、Attempt、持久 Input Snapshot、responseHash/length 和预期 type/schema 强绑定。
- Snapshot、Artifact、Issue 及其引用的大文本 document/chunks 建立引用后不可更新或删除。
- Provider metadata、错误详情和普通日志经过白名单、凭据检测与正文脱敏。
- 文件数据库关闭再打开后，可完整读取 Task、Attempts、Snapshots、Artifacts 与 Issues。

## 5. 未覆盖与版本边界

- 未迁移生产 Provider Adapter，未调用真实 AI API。
- 未实现 PlacementProposal、ApplyPlan 或正式正文自动写入。
- 未实现 Planner、Memory、Tool Registry、execution lease 或自动续跑。
- 未实现 Multi-Agent 编排或自主逐章创作。

这些内容不是 v2.3.0 的缺失验收项，而是后续独立版本目标。下一版本为 v2.3.1 Provider Adapter 与统一执行管线；届时只进行一次低输出真实 API 验收。
