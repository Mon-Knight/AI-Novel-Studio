## 1. 验收范围

本版只验收固定 `chapter_readiness_plan_v1`、SQLite 持久事实、Rust execution lease、append-only Attempt/Checkpoint、显式 retry、跨重启恢复、九工具 Registry 契约和写作工作台计划卡片。Memory、正文副作用、自动续跑、动态规划与 Multi-Agent 不在本版完成声明中。

## 4. 安全审计

- Registry hash 在 TypeScript 与两个 Rust 权威验证点同步为 `846a38c25bba33c843b56fa6583b334bae3364073fb7f0b6290be0c405aae871`。
- 原始 lease token 不进入表字段、Checkpoint、普通日志或序列化 LeaseRecord；SQLite 只保存 SHA-256。
- Tool output 在本地 canonical 化、限制 2 MiB、拒绝疑似凭据；Checkpoint 只保存 identity/hash/安全错误。
- 浏览器无 LocalStorage Planner；生产 Provider `allowedTools=[]` 不变。

## 5. 真实 API

本版只增加本地只读 Planner Tool Calling，没有修改 Prompt、Provider messages、Provider Adapter 或模型 Tool Calling 协议。根据用户“真实 API 要尝试但不要使用太多、未涉及场景可不测”的约束，本版不发起真实 API 请求；v2.4.0 的单次 8-token 外部失败记录不被改写。

## 6. Windows E2E 与安装包

完整 Windows Tauri E2E 13/13 通过。新增 `chapter-readiness-planner.spec.ts` 包含两个用例：其一从工作台创建章节并运行六步本地 DAG，读取 Plan/Step/Attempt/Checkpoint，验证 readiness 缺失项、Attempt 次数、Checkpoint 顺序和零网络；其二在第一步被 claim 且 Attempt 为 running 时真实重启 Tauri，验证 Plan/Step 进入 `waiting_retry`、原 Attempt 进入 `abandoned` 且没有自动重放，再由用户在工作台显式继续产生 Attempt 2 并完成计划，第二次重启后 Attempt/Checkpoint 数量保持不变。其余 12 项覆盖启动、项目/章节、大文本、Provider/Safe Apply、采用、离开保护、取消、恢复、质量历史与上下文持久化。
