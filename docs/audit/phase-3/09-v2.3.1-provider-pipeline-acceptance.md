# v2.3.1 Provider 管线验收报告

验收日期：2026-07-26
分支：`codex/v2.3.1-provider-pipeline`
基线：`v2.3.0`（`46d2491`）
目标：把首批生产 AI 调用接入 v2.3.0 执行事实层，并保持候选结果只读、凭据瞬时和 Provider 单次派发。

## 1. 范围结论

本版本新增统一 Provider Adapter 与执行管线，迁移设置中心连接测试和“设定补充”两个入口。桌面执行固定经过 Task / 三 Snapshot、Attempt queue/claim、Provider、response identity 和 ResultArtifact；浏览器回退明确标记为 ephemeral。

设定候选不会自动写入正式设定。PlacementProposal、ApplyPlan、Planner、Memory、Tool Registry、跨重启续跑和 Multi-Agent 均不在本版本实现。

## 2. 执行与安全不变量

- Provider 网络请求最多派发一次；`DATABASE_COMMIT_UNKNOWN` 只重放同身份持久化步骤。
- completed operation 重放读取首次 Artifact，不再次消耗 Provider 额度。
- AbortSignal 复用 Tauri HTTP 取消注册表；取消和迟到响应不能创建 Artifact。
- API Key 与 Base URL 只进入瞬时 Adapter / Tauri 参数，不进入 Task、Snapshot、Artifact、Issue 或普通日志。
- Tauri 字符串 Provider 错误保留已脱敏消息；鉴权/权限错误和请求参数拒绝为不可盲重试稳定错误码。
- `setting_candidates` Artifact 只进入候选 UI；只有用户显式确认后才调用既有正式设定写入。

## 4. 真实 API 手动验收

按“少量 API”约束只执行一次 8-token 连接测试，没有连续重试：

```text
scope                 = system
expectedArtifactType  = generic_text
maxTokens             = 8
Task status           = failed
Attempt count/status  = 1 / failed
Snapshot counts       = 1 input + 1 context + 1 constraint
Artifact count        = 0
```

持久事实扫描未发现 `apiKey`、Authorization、Bearer、配置 Base URL 或 DeepSeek 风格密钥标记。本机 DNS 与 TCP 443 连通；Provider 返回失败，但旧 Tauri 字符串错误在当次构建中被折叠为泛化消息，因此不能权威判断是鉴权、账户还是 HTTP 请求拒绝。

验收后已修复字符串错误保留和 400/401/403 稳定分类，并通过无外网动态测试。为遵守只调用一次的限制，没有重新发送真实 Provider 请求。因此 PA-REAL 结论为**未通过**，没有用 Mock 成功结果替代。
