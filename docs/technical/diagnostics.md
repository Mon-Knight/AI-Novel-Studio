# 诊断与崩溃报告

> 适用版本：v3.0.0。诊断数据默认只保存在本机，不自动上传，也不发起遥测网络请求。

## 1. 采集范围

| 来源                  | 触发                                                               | 本地上限                                        | 保存内容                                               |
| --------------------- | ------------------------------------------------------------------ | ----------------------------------------------- | ------------------------------------------------------ |
| 前端 `appLogger`      | 统一错误入口、`window.error`、未处理 Promise、React Error Boundary | 最近 50 条 error                                | 时间、事件名、错误码、重试属性及脱敏身份元数据         |
| Tauri 原生 panic hook | Rust 进程或工作线程发生 panic                                      | 导出最近 50 条；日志文件达到 128 KiB 时单代轮换 | 时间、应用版本、`rust_panic`、源码文件名和行列号       |
| AI 性能监控           | Provider 请求成功、失败或取消                                      | 最近 500 个样本                                 | Provider / 模型身份、任务类型、耗时、结果和 Token 合计 |

原生 panic hook 在数据库和窗口初始化前安装，因此启动阶段 panic 也能留下最小信封。
panic payload、错误正文、堆栈、绝对源码路径和线程名称均不写入原生报告。

## 2. 脱敏边界

前端诊断递归清理并限制深度、数组长度、字段数和单字符串长度。以下字段按键名失败关闭：

- API Key、Authorization、cookie、password、secret、token；
- Prompt、请求 / 响应 body、正文 content / text / raw；
- Provider 原始错误或响应正文。

`traceId`、`operationId`、错误码、是否可重试、Token 数量和安全的实体 ID 可以保留，
用于把用户报告与本地操作链路关联。诊断导出不包含作品正文或正式数据库内容。

## 3. 用户操作

在“设置 → 诊断与崩溃报告”中：

1. 查看前端报告数、原生报告数，以及 AI P50 / P95、失败和取消计量。
2. 点击“导出诊断报告”，显式选择 JSON 保存位置。
3. 点击“清空本地报告”并确认，删除前端、原生和 AI 性能诊断。

导出 schema 2 包含 `reports`、`nativeCrashReports` 和 `aiPerformance`。浏览器开发模式没有
Rust 进程，原生报告数组固定为空；桌面模式通过受限 Tauri IPC 读取本机报告。

## 4. 生命周期与隐私

- 应用不内置远端崩溃上传端点，不在后台自动传输诊断。
- 用户只有在主动导出并自行提交文件后，报告才会离开本机。
- 前端报告存储于应用 WebView 的 LocalStorage；原生报告位于应用数据目录，使用有界 JSONL 文件。
- 清理失败会显示统一错误并进入脱敏前端日志，不返回包含本机路径的底层 I/O 信息。

## 5. 能力边界

崩溃报告用于定位异常，不等同于未保存正文恢复。dirty 正文由独立恢复快照负责；进程发生
硬终止、系统断电或 `abort` 时，panic hook 可能没有执行机会。重新启动后应先处理工作区恢复，
再按需导出诊断。正式发布仍应结合 GitHub Actions 失败产物、Windows 桌面 E2E 和用户主动提供的
本地报告进行定位。
