# AI Novel Studio UI 参考设计文档

版本：v0.1.0 草案  
项目名称：AI Novel Studio  
项目路径：F:\ai-novel-studio  
目标平台：Windows 桌面端  
技术路线：Tauri + React + TypeScript + SQLite  
开发方式：VS Code + Copilot / Agent 辅助开发

> 文档演进说明：第 1～17 节记录 v3.2.1 及更早版本的页面基线。v3.3.0 及后续版本的目标 UI 以第 18 节和 [`architecture/conversational-creative-workbench.md`](architecture/conversational-creative-workbench.md) 为准。v3.5.0 已完成工作台、确认/审阅与写作工作台 AI 面板生产入口收敛。

---

# 1. 文档目的

本文档用于约束 AI Novel Studio 的 UI 方向，避免项目在开发过程中被做成普通网页后台、数据管理系统或简单表单工具。

AI Novel Studio 的界面应接近 Windows 桌面写作软件，参考用户提供的“作家助手”类软件界面：

1. 首界面：作品管理首页
2. 核心工作台：左侧卷章树 + 中间正文编辑区 + 右侧竖向工具栏
3. 右侧设定栏：点击图标弹出面板，可自动收回，不长期占用正文区域

本项目 UI 的核心目标是：

```text
像一个真正的 Windows 小说创作软件，
而不是普通网页后台。
```

---

# 2. UI 总体定位

AI Novel Studio 的 UI 应分为两类核心界面：

```text
AI Novel Studio
├─ 作品管理首页
│  └─ 负责作品创建、作品导入、风格方案、创作资产、设置入口
│
└─ 写作工作台
   └─ 负责按章节调用 AI，生成正文、修改正文、润色、检查、确认采用
```

其中：

- 主界面负责“创作资产准备”
- 工作台负责“AI 章节生成与正文编辑”
- 右侧栏负责“临时调用已有设定和生成控制”
- 复杂配置不堆在写作工作台里

---

# 3. UI 设计原则

## 3.1 桌面软件感优先

界面应接近 Windows 桌面应用，而不是网页 Dashboard。

应具备：

- 固定左侧导航
- 固定顶部状态栏
- 清晰的内容分区
- 作品卡片
- 编辑器工作区
- 右侧工具栏
- 桌面端窗口适配
- 较低视觉噪音
- 轻量边框和浅色背景

避免：

- 大量网页式 Banner
- 过度炫彩渐变
- 后台管理表格风
- 大量全宽表单
- 移动端优先布局
- 所有按钮堆在页面顶部

---

## 3.2 首页像作品管理软件

首页应接近用户提供的第一张参考图。

关键词：

```text
作品库
新建作品
导入作品
模板中心
作品卡片
左侧导航
顶部状态栏
```

首页不是“后台首页”，而是“小说作品管理首页”。

---

## 3.3 工作台像专业写作软件

写作工作台应接近用户提供的第二张参考图。

关键词：

```text
顶部工具栏
左侧卷章目录
中间正文编辑区
右侧竖向工具栏
底部字数统计
```

但需要注意：AI Novel Studio 与普通写作软件不同。

普通写作软件是用户主要手写正文。

AI Novel Studio 是：

```text
右侧面板选择设定、角色、事件、风格、输出控制
↓
AI 生成一章正文到中间编辑区
↓
用户修改 / 重生成 / 润色 / 检查
↓
用户确认采用
```

因此，中间正文区应被设计为：

```text
AI 生成正文输出区 + 用户可编辑区 + 版本确认区
```

---

## 3.4 右侧栏是弹出式生成控制台

右侧栏应接近用户提供的第三张参考图。

要求：

- 右侧固定一列竖向图标栏
- 点击图标后，从右侧弹出功能面板
- 再次点击同一图标可以收回
- 点击正文区域可以自动收回
- 切换章节时可以自动收回
- 面板不长期占用正文空间
- 工作台不展示复杂配置管理页面

右侧栏不是“完整设置中心”，而是“本章生成调用面板”。

# 4. 全局视觉风格

## 4.1 色彩方向

推荐使用浅色桌面软件风格。

基础色建议：

```text
应用背景：#F5F7FA
主内容背景：#FFFFFF
侧边栏背景：#F3F6FA
边框颜色：#E5EAF0
主色：#2F80ED 或 #2563EB
文字主色：#1F2937
文字次级：#6B7280
弱提示文字：#9CA3AF
危险色：#EF4444
成功色：#16A34A
警告色：#F59E0B
```

注意：

- 首页可以有轻微蓝色强调
- 工作台应更克制，避免干扰写作
- 正文编辑区以白色或极浅灰为主
- 不建议大面积深色背景作为默认主题

---

## 4.2 字体方向

默认字体建议：

```css
font-family: 'Microsoft YaHei', 'Segoe UI', Arial, sans-serif;
```

正文编辑区字体建议：

```css
font-family: 'Microsoft YaHei', 'SimSun', 'Segoe UI', sans-serif;
```

字号建议：

```text
导航文字：14px
普通正文：14px - 15px
卡片标题：16px
页面标题：20px - 24px
正文编辑器：18px - 20px
正文行高：1.8 - 2.0
```

---

## 4.3 边框与阴影

整体风格应轻量，不要厚重阴影。

建议：

```css
border: 1px solid #e5eaf0;
box-shadow: 0 4px 12px rgba(15, 23, 42, 0.04);
border-radius: 8px;
```

首页卡片可以使用轻微阴影。

工作台正文区尽量减少阴影，保持阅读舒适。

---

# 5. 应用窗口结构

Tauri 桌面窗口建议：

```text
默认窗口宽度：1280px
默认窗口高度：820px
最小窗口宽度：1100px
最小窗口高度：720px
允许最大化：是
默认全屏：否
```

2K 屏幕适配要求：

- 内容区域不要无限拉宽
- 首页卡片可以增加列数
- 正文编辑区保持舒适阅读宽度
- 设置页和表单页不应全屏拉成过宽表单

建议最大内容宽度：

```text
首页主内容最大宽度：1440px - 1600px
表单类页面最大宽度：960px - 1080px
正文编辑区正文宽度：760px - 920px
```

# 7. 作品详情页

## 7.1 作品详情页定位

作品详情页是“创作资产管理中心”。

它不负责正文生成，而负责准备写作所需资产。

主要模块：

```text
基础设定
大纲管理
角色库
风格方案
输出控制方案
导入导出
进入写作工作台
```

---

## 7.2 作品详情页布局

建议布局：

```text
┌─────────────────────────────────────────────────────────────┐
│ 作品标题 / 题材 / 当前进度 / 进入工作台按钮                  │
├─────────────────────────────────────────────────────────────┤
│ 概览卡片：总字数 / 章节数 / 已采用章节 / 风格方案 / 角色数     │
├─────────────────────────────────────────────────────────────┤
│ 基础设定     大纲管理     角色库     风格方案     输出控制     │
├─────────────────────────────────────────────────────────────┤
│ 当前模块内容区域                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 7.3 基础设定模块

基础设定应包含：

```text
世界背景
魔法 / 科技 / 规则体系
主角设定
主角特殊能力
```

输入原则：

- 不要求用户填写完整世界观
- 用户只提供大致方向
- 后续由 AI 辅助结构化整理
- 允许用户随时修改

---

## 7.4 大纲管理模块

大纲管理应包含：

```text
分卷大纲
章节大纲
当前剧情进度
```

早期版本可先做文本输入与列表展示。

后期扩展 AI 辅助：

```text
扩展分卷大纲
生成章节列表
检查大纲断裂
补充章节目标
```

---

## 7.5 角色库模块

角色库应包含：

```text
主角
已生成角色
AI 候选角色
角色关系
角色目标
角色限制
不能做出的行为
```

注意：

- AI 候选角色需要用户确认后才进入角色库
- 已生成角色后续再次出场时必须读取已有状态
- 不允许每次重新随机生成同一个角色

---

## 7.6 风格方案模块

风格方案在作品详情页或单独“风格方案”页管理。

功能包括：

```text
TXT 导入分析
JSON 导入配置
手动创建
已保存风格画像
```

风格方案不应完整堆到写作工作台里。

工作台只需要选择：

```text
本章使用风格方案：黑暗奇幻稳重风
```

---

## 7.7 输出控制方案模块

输出控制方案用于管理章节生成参数。

示例方案：

```text
默认章节
战斗章节
日常过渡
高压冲突
结尾爆点
```

每个方案包含：

```text
目标字数
节奏
对话比例
描写比例
战斗强度
情绪倾向
结尾钩子
禁用写法
```

工作台只调用方案，不负责完整编辑。


# 18. v3.3.0+ 工作台 UI 目标（已实现）

## 18.1 默认首界面

应用启动后进入对话式创作工作台，而不是作品卡片首页。工作台使用稳定的双栏主布局：

```text
左侧：小说项目 / 任务树
中央：对话、内联工具调用、错误与产物卡片
底部：任务级模型选择、输入框、发送或停止
```

顶部只保留当前任务的小说、标题、模型和运行状态等必要信息。主界面不增加后台式统计仪表盘。

## 18.2 左侧项目与任务树

- 小说是一级分组，任务对话是二级条目。
- 任务条目以轻量徽标显示运行中、需要用户处理、失败和已完成。
- 左侧提供新建、搜索、归档和恢复，不展开任务计划、工具列表或产物详情。
- 用户切换任务不会取消后台执行。

## 18.3 对话消息与工具行

工具调用插入发生位置，采用紧凑的“语义名称 + 技术名称 + 状态 + 耗时”结构：

```text
✓ 读取小说上下文   novel.read_context      0.3s
✓ 读取章节大纲     chapter.read_outline     0.2s
✓ 检索长期记忆     search_memory            0.8s
● 生成章节候选     generate_chapter         运行中
```

失败时，对应调用行变为错误状态并显示可公开的原因、重试或修复动作。UI 不显示模型思维链，也不设置独立的“对话与执行时间线”“任务计划”或“工具”面板。

## 18.4 产物卡片

产物卡片只在候选完成持久化并通过校验后出现。卡片必须显示：

- 产物类型、目标小说/章节和基线；
- 变更摘要、验证状态与模型来源；
- 待处理、需修订、已确认、应用中、已应用、冲突、拒绝或失效状态；
- 查看、要求修改、确认、应用、拒绝等与产物类型匹配的操作。

卡片正文可以展开或打开专用审阅界面，但不建立独立“产物详情”主页面。

## 18.5 任务级模型选择与并发反馈

- 模型选择器位于输入区附近，并始终明确作用于当前任务。
- 更换模型只影响后续运行，历史消息和产物继续显示原模型快照。
- 不同任务可以选择不同模型并并发运行。
- 项目树和任务标题区都要显示足够的后台运行状态，避免用户切换后误以为任务停止。

## 18.6 旧页面收敛

- 导航中的“待确认”删除；待处理状态由任务徽标和产物卡片承载。
- 小说作品页保留并优化为项目管理入口，作品详情不再显示“待确认产物”。
- 原写作工作台改为章节人工审阅/编辑器，默认只读，显式进入编辑、保存和采用。
- 删除草稿版本查看入口。
- 生产写作工作台右侧栏只保留保存、草稿、章节准备、总结、排版和采用；生成/大纲/角色/事件/风格/检查/润色入口已迁入创作工作台任务对话。
- 桌面 E2E 仍可通过 `VITE_AI_NOVEL_STUDIO_E2E` 打开既有作业链路面板，作为回退验证，不作为产品主入口。

## 18.7 当前插件只读视图

工作台提供一个轻量“当前插件”入口，打开后显示 Runtime 实际加载的插件，而不是维护独立的前端插件清单。

- 顶部或侧部筛选仅包含“全部 / 功能插件 / 模型插件 / 其他插件”；
- 列表项显示名称、分类、版本、简短说明和加载状态；
- 只读详情显示功能插件提供的工具/能力、模型插件提供的 Provider/模型，或其他插件的运行时职责；
- 状态至少覆盖已加载、加载失败和不可用；
- 页面保持紧凑桌面列表与详情布局，不使用后台管理表格或统计仪表盘；
- 不出现安装、卸载、启停、配置、更新、权限、市场或项目绑定操作；
- 该页面不显示任务计划、执行时间线或某次任务的工具调用详情，实际调用仍在任务对话中内联显示。

完整状态、交互与迁移边界见 [`architecture/conversational-creative-workbench.md`](architecture/conversational-creative-workbench.md)。

# 19. UI 最高优先级总结

AI Novel Studio UI 的最高优先级是：

```text
第一：对话式创作工作台是默认首界面
第二：小说是项目，任务对话可独立切换并发运行
第三：工具、错误和产物在对话发生位置内联显示
第四：任务级模型选择清晰，历史运行来源可追溯
第五：旧写作工作台收敛为人工审阅/编辑器
第六：当前插件只读展示与 Runtime Registry 保持一致
第七：整体像 Windows 桌面创作软件，不像网页后台
```

所有 UI 开发都应围绕以上目标展开。
