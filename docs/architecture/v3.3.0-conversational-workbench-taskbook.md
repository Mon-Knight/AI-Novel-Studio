## 4. 当前实现不能被误判为完成的阻断项

### P0-1：当前 `taskSessionAdapter` 不是真正的 Harness 执行

当前 `src/services/dsh/taskSessionAdapter.ts` 的桌面路径已经委托 `dshTaskRuntimeService`，Rust `task_runtime.rs` 也会启动 DSH child、发送一次 `session/prompt`、消费部分 `session.event` 并等待 idle；因此不能再把它描述成“桌面端仍直接调用前端 adapter”。但当前实现仍不是目标中的持续多轮 Harness 工作台：

- 每个 run 创建新的 `workerId` 和临时 `session_root`，回合结束后关闭 runtime；
- 虽然 `sessionId` 字符串稳定，但后续消息没有从固定 Session 存储调用 `ctx.agents.resume` 或等价公开恢复机制；
- 失败回合在 Rust 返回错误后没有形成可继续的 assistant 错误消息，界面只剩运行块；
- 浏览器 fallback 的 `taskRuntimeAdapter` 仍按硬编码顺序执行工具；
- 当前证据不能证明 follow-up 使用同一 Harness Agent/Session 历史，也不能证明 Agent 公共 inbox/cancel/idle 语义已被复用。

只要这条仍成立，v3.3.0 就不能声明完成。

### P0-2：产物卡片形成了第二份产物正文

当前 `conversation_artifact_cards` 保存 `artifact_type/title/summary/content/status`，而既有 `result_artifacts` 才是候选产物权威事实。

必须改为：

```text
DSH / Provider 有效输出
→ 既有 AI Task / Attempt / ResultArtifact 管线
→ ResultArtifact 持久化并完成校验
→ Conversation Artifact Projection 只引用 artifactId
→ UI 从 Artifact Service 读取显示内容
```

对话卡片不能独立保存另一份可分叉的候选正文，也不能从 assistant 文本解析产物。

### P0-3：当前插件状态是合成值，不是实际 Runtime 状态

当前 `currentPluginService.ts` 主要通过前端 Tool Registry、单一 AI 设置和 `isTauri()` 合成插件列表；进入 Tauri 不能自动等于 DSH 已加载。

必须建立稳定只读 Projection：

- ANS 功能插件来自实际 production Tool Registry manifest；
- 模型插件来自当前可用 Provider/Model directory，而不是单一硬编码卡片；
- DSH/其他插件来自载体 manifest、Cordis composition 与实际初始化/健康结果；
- 载体缺失、commit 不符、插件加载失败和模型不可用必须显示真实状态；
- React 不接触 Cordis 对象，不硬编码插件清单。

### P0-4：现有并发只证明前端 Promise 并发

当前测试能证明两个前端任务有不同 run/workerId，但不能证明两个真实 DSH Worker 同时运行、取消隔离和故障隔离。

必须增加真实 Rust Worker 管理和动态测试。

## 7. 详细实现要求

## 7.1 建立真实 DSH Task Runtime

在现有 `src-tauri/src/services/dsh/` 基础上扩展通用任务运行能力，不复制另一套 supervisor。

至少提供以下稳定 ANS 协议：

```text
describe_runtime
start_task_turn
cancel_task_run
get_task_runtime_status
list_current_plugins
```

具体 Tauri command 名可按现有命名风格调整，但前后端必须有显式类型和动态测试。

### Worker/Session 规则

- 一个 TaskConversation 使用稳定 `sessionId` 和 `agentId`；
- 一个活动任务拥有独立 Worker/DSH child/Windows Job Object；
- 同一 conversation 同时只允许一个活动 run；
- 不同 conversation 至少允许两个真实 Worker 并发；
- 切换 UI 中的任务不停止后台 Worker；
- follow-up turn 复用同一 Harness session identity 和固定 session root；
- run 完成后可以释放 child，但不能丢失后续恢复 Session 所需事实；
- DSH session storage 可丢弃/重建，ANS conversation/run/tool/artifact facts 不可依赖它作为唯一恢复来源。

### 启动与初始化

- 使用现有 `runtime_root()`、`NodeDshRuntime`、`RuntimeHandle`、Cordis template、model proxy 和 pinned payload；
- 启动前校验 Node、载体目录、`VERSION_MATRIX.json`、固定 commit、runtime bin 和 gateway；
- `initialize` 成功且 Loader settle 后才能把 runtime/plugin 状态标记为 loaded；
- 每次 run 使用冻结的 model snapshot 构造 DSH provider/model/options；
- 不把 API Key写入 Cordis 文件、Session、SQLite 或普通日志。

### Turn/Step 与事件

- 按固定源码的 Agent 公共 API 创建或恢复同一 `SessionId`，用户首轮与 follow-up 通过 Agent inbox 进入真实 Turn/Step；不得把 one-shot `dsh --profile headless "task"` 每轮重启伪装成持续对话；
- Harness 决定调用哪些允许工具，ANS 不再为桌面 DSH 路径硬编码工具顺序；
- 消费 `session.event`/`session.status` 并映射 assistant、tool call、tool result、error、turn end；
- 事件必须先持久化，再通知 React；
- UI 刷新或重启后从 SQLite 重建，不从内存或 JSONL 猜测；
- 未知事件保留安全类型/摘要并使用通用 renderer，不能导致整个回合丢失；
- tool call 与 result 通过稳定 callId 关联；
- 工具失败在对应调用处进入终态，run/turn 同时记录安全错误摘要。

### 取消与故障

- 取消一个 run 只终止对应 Worker/Job Object；
- 已开始工具调用必须收敛为 succeeded/failed/cancelled；
- 未开始调用标记 skipped 或不创建，语义保持一致；
- child crash、stdout 协议错误、超时和 app restart 都必须形成持久失败/取消终态；
- 不允许一个 Worker 的 stderr/stdout 污染另一任务；
- 启动恢复幂等，多次恢复不能重复修改终态。

## 7.2 模型选择与请求治理

- 模型选择器显示当前可用模型，而不是只有硬编码 Mock 和单一 DeepSeek；
- 模型目录可来自现有 Provider 设置与 Runtime Projection，不建设模型插件管理；
- 每个 conversation 保存默认模型；
- 每次 run 冻结 Provider、modelId、参数、价格、Runtime/DSH commit、Bundle/Profile 和 Adapter protocol；
- 用户切换模型只影响后续 run；
- 历史消息、run 和 artifact 继续显示原模型来源；
- 不支持所需 Tool Calling 的模型发送前明确失败，不能静默换模型。

DSH 的上游模型调用必须接入现有全局请求治理：

- 派发前 reservation；
- 唯一 request identity 与 lease/fencing；
- 成功按真实 usage 结算；
- 缺 usage、失败、取消、超时按现有保守规则结算；
- 并发/频率/日 Token/成本门禁对普通 Provider 和 DSH 一致；
- proxy 不得成为绕过 Rust 权威门禁的第二出口。

## 7.3 四个首批领域工具

- 参数和结果日志只保存安全摘要，大文本通过引用保存；
- 工具错误使用稳定错误码和公开摘要；
- 浏览器开发 fallback 可以使用确定性 Runtime，但必须明确显示 `ans-provider-fallback`，不能标记为 DSH。

## 7.4 修正 ResultArtifact 与卡片投影

要求：

- migration 必须兼容当前分支已运行过 032/033 的本地开发数据库：根据现状安全演进，不通过删除用户数据库解决；

## 7.6 工作台 UI

默认 `/` 打开 Workbench；`/novels` 和现有旧路由继续可访问。

布局：

```text
左侧：小说项目 / 任务树
中央：当前任务对话
底部：任务级模型选择 / 输入 / 发送或停止
轻量入口：当前插件只读视图
```

要求：

- 小说项目作为一级分组，任务作为二级条目；
- 创建任务必须绑定 novelId；
- 任务显示 idle/running/waiting_user/failed/completed/archived 状态；
- 切换任务不取消后台运行；
- 对话按持久 sequence 渲染用户消息、AI 消息、工具行、错误和产物；
- 工具行显示语义名、技术名、状态、耗时和安全摘要；
- 错误附着在发生位置；
- 产物卡片只在 ResultArtifact 完成持久化和校验后出现；
- 模型选择器始终明确作用于当前任务；
- 支持发送、停止、重试失败回合；重试创建新 run，不覆盖旧 run；
- 2K 与 1280px 最小宽度可用；
- 不做网页后台表格，不做大面积渐变；
- 不显示模型隐藏思维链或 reasoning 原文。

## 7.7 持久化、约束和恢复

保留并补强 migration 032/033 或增加安全后续 migration，满足：

- conversation 属于一个 novel；
- turn 按 conversation 单调有序、append-only；
- run 属于同 conversation 的 turn；
- 同 conversation 最多一个活动 run；
- model/runtime snapshot 为合法 JSON 且不可被历史改写；
- tool event 属于一个 run，callId/sequence 稳定，终态不可改写；
- artifact projection 引用同 conversation/turn/run 和真实 ResultArtifact；
- archive 不删除已经应用/引用的领域事实；
- restart recovery 幂等；
- backup/restore、项目删除和外键行为有动态测试；
- 浏览器 LocalStorage fallback 只用于开发，不冒充桌面权威。

## 10. 验收标准

只有同时满足以下条件才能声明 v3.3.0 完成：

1. 默认首页是对话式创作工作台。
2. 小说是项目，项目下任务可以创建、切换、重命名/归档（若现有 UI 已提供）并持久恢复。

4. 至少两个真实 DSH Worker 可以并发。
5. 取消一个任务不会终止另一个任务。
6. 每次 run 冻结独立模型/Provider/Runtime 快照。
7. Harness 根据用户目标调用 allowlist 内工具。
8. 工具调用、结果、错误和取消从持久事件投影到对话。
9. `generate_chapter` 产生真正的 ResultArtifact。
10. 产物卡片只引用 ResultArtifact，不保存第二份正文。
11. 普通 assistant 消息或工具成功不能证明正式正文已写入。
12. 当前插件视图读取真实 Projection，并且完全只读。
13. 应用重启后任务、run、工具终态和 artifact 引用可重建。
14. 旧作品页、作品详情和写作工作台仍可使用。
15. 没有实现 v3.4/v3.5 范围。
16. 第 1～15 项和全部非打包测试先通过，验证记录证明没有提前运行打包。
17. 完整实现后未打包 Release 主程序构建和桌面测试通过。
18. 版本同步为 3.3.0，工作树只包含本任务合理变更。
19. `reports/full-workbench/dsh-source-map.md` 完整映射固定提交源码、复用 API/事件、ANS Adapter、必要差异和动态测试；不存在无源码依据的自制 Agent Loop。

以下任一情况必须判定未完成：

- DSH 仍只是 TypeScript Adapter 的标签；
- 没有固定提交 source map，或用自行编写的状态机替代 Harness Core Agent/Session/Tools 公开机制；
- 把官方 one-shot headless runner 每轮重启后包装成“持续多轮对话”；
- 桌面 DSH 失败后静默执行固定工具序列；
- 插件列表由 React 硬编码或只凭 `isTauri()` 标记 loaded；
- 卡片正文与 ResultArtifact 各存一份；
- 并发只用两个 Promise 测试，没有 Worker 隔离证据；
- 只通过 build，没有动态测试和桌面 E2E；
- 在实现或非打包验收尚未完成时提前运行打包；
- 删除了旧 UI 或提前实现确认/应用。
